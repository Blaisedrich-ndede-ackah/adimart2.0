Tech stack (if you're building something similar)

Adimat runs entirely in the browser as a static client with no first-party application server. Here's the stack behind it:

LayerTechnology
FrontendReact 19 + Vite + Tailwind CSS + TypeScript
StateZustand (auth + cart), swr
Local databaseIndexedDB via Dexie.js (AdimatPOS database)
Cloud sync / backendSupabase + PostgreSQL (optional backup/restore, Row Level Security)
PaymentsPaystack Inline (Mobile Money, card, bank, USSD, QR)
HardwareZXing barcode scanning, Web Bluetooth ESC/POS printing, WebAuthn biometrics
Receiptsjspdf (PDF receipts, #ADM-YYYYMMDD-XXXX format)
DeployStatic hosting (Vercel / Netlify), PWA install via service worker, single-file bundle via vite-plugin-singlefile

One critical implementation note

Adimat is a PWA with state-based navigation (no react-router-dom), so most content lives behind authentication. If you want SEO and easy crawling, build your public marketing pages using static generation or server-side rendering (e.g., Next.js SSG/SSR) so About/Privacy/Contact/Help contain real HTML text on first load. For a full URL inventory of a JS-rendered site, check sitemap.xml or run a headless browser crawler such as Playwright.

Recommended sitemap (Adimat-like)

Adimat's public presence is a focused landing page plus supporting trust pages and an auth gateway into the product:

  • Home (`/`) — Hero, product preview, proof metrics, feature grid, 3-step setup, testimonials, final CTA
  • About (`/about`) — Mission story, who it's for, why now
  • Contact (`/contact`) — Simple form + email + phone
  • Help (`/help`) — Lightweight FAQ or links to support
  • Privacy (`/privacy`) + Terms (`/terms`) — Legal trust for larger customers and partners
  • Auth (`/auth`) — Login/signup entry point into the PWA
